# Task-2 final run record (2026-08-11)

This record supplements the bounded P3 fault-injection run with the final Linux +
Zephyr P2 long-stability run. The run used the rebuilt Linux task2 initramfs and
the Zephyr image with `CONFIG_ARMV8_A_NS=y` and a 200 ms heartbeat interval.

failed before the Rust timer fix and passed afterward.

## P2 one-hour stability

Command:

```bash
cargo xtask axvisor qemu \
  --config /tmp/task2-axvisor-qemu-debug.toml \
  --qemu-config scripts/test/net-dual-guest/qemu-aarch64-p2-stability-1h.toml \
  --vmconfigs scripts/test/net-dual-guest/vm-aarch64-p2-linux.toml \
  --vmconfigs scripts/test/net-dual-guest/vm-aarch64-p2-rtos.toml
```

The process ran for 3849.75 seconds (about 64 minutes) and was stopped through
QMP. Both captures contained 37,450 Ethernet packets, 37,220 UDP/T2N1 frames,
and an identical sequence ledger:

```text
10.0.42.15 -> 10.0.42.2:  18,611 frames
10.0.42.2  -> 10.0.42.15: 18,609 frames
kinds: heartbeat=37,216 control=1 status=1 ack=2
```

The verifier and isolation checks both passed. The AxVisor log contained zero
`TASK2_SAFE`, `TASK2_RECOVERED`, `TASK2_PROTOCOL_ERROR`, and `TASK2_SEND_ERROR`
events.

not a saturated virtio-net capacity benchmark. The long run intentionally sends
one control transaction and then exercises liveness; a separate load test would
be needed to claim peak bandwidth.

## P3 bounded fault evidence

`verify_fault_pcap.py`: exactly one RTOS-to-Linux ACK for sequence 1 was dropped,
the reliable frame was retransmitted, and the duplicate was handled without a
second application delivery. The QMP link down/up run passed `verify_pcap.py`
and observed one `TASK2_SAFE` followed by one `TASK2_RECOVERED`.
